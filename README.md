# Product Training Sandbox

This repository is part of a structured onboarding exercise for Business Analyst. 
The goal is to get hands-on with the tools and workflows used in day-to-day 
product work — specifically GitHub for requirement tracking, documentation, 
and feature reviews.

---

## Project Goals

The work here mirrors what actually happens when a client request comes in 
and needs to move from a vague ask to a shipped feature. Specifically, this 
repo covers:

- Writing requirements in a format that engineers can act on
- Using GitHub Issues to track work and maintain a clear paper trail
- Practicing branch-based workflows so changes are always reviewable before merging
- Producing documentation that both technical and non-technical stakeholders 
  can follow

---

## Current Feature: Order Status on Dashboard

The active feature being tracked in this repo is based on a real product 
scenario — users want to see their order status without navigating away 
from the dashboard.

This was chosen because it's a common type of request: clear user need, 
defined scope, and measurable outcome. It's a good model for how most 
feature requests should be documented.

## Success Criteria

The following criteria define what "done" looks like for this training exercise:

| Deliverable | Description | Status |
|---|---|---|
| Repository setup | Repo created, named correctly, visible publicly | ✅ Done |
| GitHub Issue | User story written with acceptance criteria and context | ✅ Done |
| README documentation | Project goals and success criteria clearly documented | ✅ Done |
| Branch + Pull Request | Change made on a separate branch, PR linked to Issue | ⬜ In Progress |

---

## How This Repo Is Structured

For now this is a documentation-only repo. As the exercise progresses, 
branches will be used to propose and review changes — same as a real 
engineering workflow.

All work here is part of a Business Analyst training program. Issues and
